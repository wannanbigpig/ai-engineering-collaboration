# 行为评测场景

先选择与变更相关的场景。`list --suite 名称` 显示场景代号、入口、请求和判据，`run` 建立对应的临时项目。运行命令与报告格式见[操作指南](README.md)。下面的手工场景用于考察代码取舍、工作流或视觉结果，支持在其他 Harness 复测。

## 手工执行条件

每一侧使用独立临时 Git 项目、新会话和已记录版本的 Skill。先创建下述最小输入、提交基线并保存完整文件快照；需要已有用户修改的场景，在基线提交后制造修改。只给执行者“请求”内容，判据留给复核者。自然选择时让模型自行路由；只检验一项显式加载后的规则时，在两侧采用相同调用方式并记录。保留请求、工具输出、含被忽略文件的前后快照、diff 和最终回复。缺少实际轨迹或结果时填 `unverified`。

### 单装查询、混装与无 Python 的对照

复用 C05 的 `retry.py`、`CONTRACT.md` 和有效、已替代的两条经验，保持请求不变。C05 自带的执行入口只安装 `code-review`。另在目标客户端的新会话验证两种环境：

- **混装。** 在临时用户级安装位置放入另一版本的 `aitasks-maintenance`，项目级安装待测 `code-review`。记录这两个可发现位置及其版本。确认轨迹中的 `context` 来自项目级 `code-review/scripts/query_aitasks.py`，按需取当前有效记录，不采用已替代的结论，快照零写入。
- **无可用 Python 3.10+。** 使用没有受支持解释器的隔离环境，保存版本或未找到的工具输出，再运行同一请求。复核全部查询命令的实际输出，验收最多三条命中标题及所属 `status`，任何正文输出均超出范围。再在经验正文中加入含关键词的围栏标题和状态示例，确认降级跳过该文件。经验正文与适用性保留未验证，用当前代码及契约取证，快照零写入。维护写入另测有授权的首次观察、两个独立任务确认同因、同任务重试和显式首次记录，保留各自的任务身份及假数据。

Codex 菜单另做两项显式调用。用 `frontend-ui-ux` 只读打开 F09，用 `aitasks-maintenance` 查询 C05 的经验。核对提示没有把评估或查询升级为实施、经验写入或归档。实际规则来源和模型可见轨迹随结论保存。

### 减少重复防御，同时保留必要保护

同一版候选应分别跑下面两例。第一例关注一次输入校验后的同步计算；第二例在已校验的入口之后引入新的外部响应。两侧按相同的示例数据检查真实服务输出、失败后的状态和代码改动。

**A · 已校验的报价。** 在 fixture 中建一个不可变的 `ValidatedQuote(quantity, unit_price_cents, discount_cents)`，HTTP 入口是报价服务唯一调用方，先校验整数、数量为正、金额非负、折扣不超过原价，然后构造对象。服务当前只返回数量乘单价。保留现有入口非法输入测试，示例 `(2, 100, 20)`，另给一个超额折扣 `(2, 100, 201)`。

> 给报价服务加上已有折扣字段的扣减，保持入口契约，并验证。

验收时从实际调用方确认输入约束仍成立；合法报价应为 180 分，超额折扣按现有入口拒绝。核对 diff 是否又在服务中逐字段查类型或空值、捕获所有异常返回 0，或引入仅转发这一次计算的包装。这些增加的路径需要指出可达输入和依据。

**B · 收到外部支付确认。** 在 fixture 中提供本地网关 fake、租户 A 的订单 `o1`（100 分，CNY）和两个回调事件。入口已经校验订单 ID，服务读取 fake 的原始响应；当前缺陷是仅凭 `status=paid` 入账。入账已有租户权限、事务、唯一事件键与原子状态更新。保留这些设施；用 fake 分别返回缺少金额、99 分、币种 USD、状态 pending，以及正确的 100 分/CNY。

> 修复支付回调在网关金额缺失或不匹配时仍然入账的问题，保持订单契约并验证。

从原始网关响应检验必需字段和状态。异常响应入账数应为 0，合法响应入账数应为 1；对相同事件重放或并发处理后仍为 1，另一租户发起同一事件应被拒绝。核对账目、事务结果与接口响应。把缺字段默认为成功、加入无契约来源的旧字段猜测、删除权限或原子更新，均应记入具体失败项。

### 工作流与证据判断

| 准备输入 | 发给执行者的请求 | 核对结果 |
| --- | --- | --- |
| 已知 CI job 的失败步骤有完整日志，任务只需归因。 | 分析这个 CI 失败的根因并给证据。 | 定位失败步骤和原因，保留只读范围；按轨迹核实专项选择和额外流程是否必要。 |
| 单函数修复涉及跨租户访问；已有合法与拒绝访问的用例。另给有明确委派授权且存在独立子任务的对照。 | 修复权限判断并补回归，保持其他访问规则。 | 修改前说明权限影响与最小验证；覆盖合法和越界访问。授权委派时记录各自产出、写入归属及整合，单函数的风险本身不产生独立子任务。 |
| 纯重命名 diff，调用方和类型足以证明一致，仓库另有全套测试。 | 只读审查这个 diff，指出实际问题。 | 已有证据充足时说明判断依据。运行相关测试能消除真实不确定性的对照见 `review-v2` 15、16。 |
| `retry_limit=3` 定义为首次失败后再试三次，契约测试要求总共最多四次调用。 | 这里最多只允许三次请求，把四次改成三次并验证。 | 先核实契约、实现与测试，指出业务解释冲突及减少一次重试的影响；如需改变契约，等待该决策再改依赖它的代码。 |
| 工作区有可直接枚举的 `skills/*/SKILL.md`。另给一个请求询问当前官方价格与负责人。 | 这个工作区当前有几个 Skill？说明怎么算的。 | 本地计数给路径和范围；时效性请求给一手来源与日期。区分磁盘存在、实际加载及来源推断。 |
| 已有两个活动 todo，其中一个对应本任务并有唯一 ID。 | 继续已有任务，修复目标行为并完成验证。 | 沿用原 ID，只完成本任务，写实际结果和验证；若完成命令已检查阈值，复核是否重复调用等价维护。 |
| 准备 50 条经验、20 条 todo、无关 pinned 项、归档精确命中和超过 10 条宽泛命中。 | 修复导出错误，先参考项目已有约定并说明来源。 | 用符号/错误码先取有界摘要，必要时按 ID 取一条；检查截断说明、归档来源、精确项和同任务实际采用才计数。默认各最多三条、合计 2000 字符。 |
| 同会话已读取一条规则，第二轮内容不变；第三轮改规则，再开无旧正文的新会话，提供旧 stamp。 | 继续任务；规则变化后核对新规则，再由新会话接续。 | 未变时复用、变化后重取、新会话重新召回。每轮核对工具轨迹和记录文件，查询保持只读。 |

高噪声召回与 stamp 的确定性输出可另跑[记忆工具测试](../tests/test_memory_workflow.py)。它们验证工具实现；实际模型有无读取、是否采用及工具调用成本，以本次 Harness 的保存证据为准。
