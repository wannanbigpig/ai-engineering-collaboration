# 1.6.4 审查风险与检索范围收敛结果

## 结论

保留本轮两项改动：默认审查只收录有实际调用、用户场景、公开契约、现有数据流或直接受影响行为支撑的问题；业务关键词搜索与规则发现分开，并把调用方和 Git 历史限定到审查目标。探索性加固仅在用户明确要求时单列，不计入缺陷数量或合并结论。

最终4个候选样本中，任务正确性3通过、1失败，流程效率3通过、1失败；授权边界、验证真实性和评测有效性均4通过。明确支持 `date` 和明确要求拒绝 `date` 的两个正例均通过，说明收窄默认风险没有机械漏掉真实契约问题。自然审查仍有一次把“不支持”推导成“必须拒绝”的误报；另一个正确样本仍使用无范围的 `git show --stat HEAD`，把14个Skill文件混入取证。

因此1.6.4改善了判定和搜索边界，但没有证明默认审查已稳定解决误报与过宽检索。本轮保留失败，不继续堆叠同义规则。仓库版本为1.6.4；没有提交、推送、发布或更新用户级安装。

## 根因与修改

| 问题 | 根因 | 修改 |
|---|---|---|
| 纯假设风险进入问题清单 | 旧规则要求证据，但没有在写入清单前明确区分“具体场景”与额外构造输入 | 增加三向收录门槛：已确认缺陷、风险或待确认、不收录；没有实际场景的假设输入默认省略 |
| 探索建议影响合并结论 | 可选加固与当前缺陷共用一个问题列表 | 仅在用户明确要求探索性审查或加固建议时单列“可选改进”，不计入缺陷和合并结论 |
| 业务搜索读入无关Skill和评测副本 | 规则发现和业务关键词使用同一全仓范围 | 先按路径读取适用规则；业务搜索排除已加载Skill、评测快照和辅助副本，目标本身位于这些目录时例外 |
| Git取证范围过宽 | 只约束了关键词搜索，没有同时约束调用方和历史命令 | 要求调用方与 Git 历史限定目标文件，不用无范围提交统计代替影响证据 |
| 查询Skill加载评分失真 | `precision-v4/25`、`26`的用户请求直接包含维护Skill脚本路径，却把读取所属Skill机械计为自然误触发 | 新增 `precision-v5/27`、`28`，保留相同提示和fixture，只修正评分口径；自然触发必须另用不含Skill名称和路径的请求 |

官方文档将Skill使用区分为用户显式选择/提及与基于description的自动选择；脚本路径并不是文档定义的 `$skill` 显式调用形式，但会给模型提供所属Skill上下文。因此路径场景只用于工具可用性观察，不再冒充自然触发测试，详见[官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)。

## 遗留边界

- 默认审查误报只得到单次成功与单次失败，尚未形成稳定改善证据；继续增加同义禁令可能提高规则密度，却不能保证模型判定一致。
- 搜索排除规则已在3/4最终样本生效，但无范围 Git 统计仍出现一次；当前只能报告改善，不能宣称完全消除无关读取。
- 当前样本只覆盖小型Python契约fixture和本机CLI；其他模型、Harness、真实大型仓库、CodeGraph、浏览器与UI审查未验证。
- CLI事件输出缺口的内部根因仍属于上游边界，本轮没有修改运行器或Skill去掩盖它。
