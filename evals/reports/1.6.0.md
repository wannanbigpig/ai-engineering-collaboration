# 1.6.0 优化与行为验收结果

日期：2026-09-15。规则与评测工具已落地；真实评测发现的两处验证问题已修正，并完成受影响场景复测。尚不能证明所有任务的流程成本都降低，也不能承诺模型始终遵守每条指令。

## 落地内容

| 优化 | 最终规则 | 作用 |
|---|---|---|
| 最小计划 | 非平凡实施必须先有目标、范围、切片、验证和风险；复用会话或文件计划，按项目要求持久化 | 保留必要规划，减少重复建档和批准 |
| 根因实验 | 保留多个有证据的候选，每次实验检验一个关键假设；无新证据时说明缺口 | 避免过早锁定唯一原因和无效循环 |
| CodeGraph | 只优先用于尚未明确的结构或跨模块关系 | 已知局部目标直接定位 |
| UI 与结构检查 | 复用基线，只检查受影响部分 | 降低局部文案修改引发整套检查的风险 |
| 审查反馈 | 在 `code-review` 内分流主动审查与反馈核验；核对事实后按已有授权处理 | 接受有效意见，拒绝与契约冲突的意见 |
| 验证真实性与去重 | 按退出码、输出和实际覆盖报告；相同覆盖的验证只选一种，新增覆盖仍需补测 | 修正真实样本中的空测试误报及重复执行 |

正文调整集中在现有 5 个 Skill，全部 10 个 Skill 的版本同步为 `1.6.0`。新增评测工具仅供维护者主动运行，不进入日常任务的强制流程。

## 规则层面的原因

- “按需维护计划文件”没有明确保留修改前规划义务；计划内容与持久化形式需要分开。
- “只保留一个根因”混淆了候选原因与单次实验的假设；CodeGraph 和 UI 清单也缺少适用范围限制。
- 反馈核验与完整审查没有分流，会重复套用范围和输出规则。
- 真实执行暴露了独立审查对退出码、空测试和实测证据的约束缺口；调试收尾的“复现原问题并运行相关测试”也可能被执行成重叠步骤。

## 验证方法

- 对照基线是修改前的实际 `1.5.0` 工作区，包含未跟踪源文件，共冻结 43 个文件及 SHA-256；不是较早的 Git 提交。
- Codex CLI `0.147.0`，默认模型 `gpt-5.6-sol`，runtime header 的 reasoning effort 为 `none`。两侧采用相同配置、固定请求和 fixture，各独立运行三次。
- 每个工作区与评分资料分离；单次配置禁用标准位置的外部 Skill。保存真实 JSONL、完整文件快照、源码哈希、最终回复和独立契约探针。
- 原批次为 12 组 × 两版本 × 3 次，共 72 个样本；其中验证复用组包含真实会话后续轮次。
- 发现问题后保留原候选 A 的结果，修正版 B 仅复测受影响的 `01/09/10/12` 四组，共 24 个样本。未事后更改 fixture 或评分标准，也未把两批拼成一次“全部通过”的验收。
- 两位独立评分者分别复核原批次及对应定向场景；主 Agent 复核关键失败证据、定向反馈场景和最终汇总。关键词匹配与进程退出成功均不代替行为判断。

## 实际结果

单元测试 **45 项通过**，10 个 Skill 的结构与版本校验通过，`git diff --check` 通过。96 个正式场景全部执行完毕，96 条目标 Skill 全文读取可核实；60 次适用的独立功能契约探针通过，36 个整组只读场景的内容快照未变化。另有 4 个开发试跑样本，因早期评分目录隔离不足，不计入正式结果。

下表综合预声明关键行为、验证表述和可证实的流程违规；轻微效率观察单列。它不是“所有输出细节均正确”的保证。

| 批次 | 版本 | 通过 | 失败 | 证据不足 |
|---|---|---:|---:|---:|
| 原始 72 个样本 | 1.5.0 基线 | 34 | 2 | 0 |
| 原始 72 个样本 | 1.6.0 原候选 A | 29 | 5 | 2 |
| 定向 24 个样本 | 1.5.0 基线 | 8 | 2 | 2 |
| 定向 24 个样本 | 1.6.0 修正版 B | 12 | 0 | 0 |

原候选 A 没有达到验收目标，因此进行了有证据的修正。可确认的局部结果：

- **调试重复验证**：原候选 3 次中有 2 次出现；修正版对应 3 次未再出现。
- **文案审查空测试误报**：原候选 3 次均将 `0 tests / exit 5` 描述为成功；修正版对应 3 次均跳过空测试，没有误报。
- **跨轮证据复用**：原批次两侧均在输入未变时复用测试结果、相关代码改变后重验；基线累计重读未变化 Skill 全文 6 次，候选为 0。
- **反馈处理**：定向场景两侧均 3/3 接受正确反馈、拒绝违反明确契约的反馈，并完成授权内修复；没有观察到重复授权等待。

这些结果支持保留最小修正，但样本不足以证明普遍效率改善。没有给出固定耗时、tokens 或费用节省比例。

## 保留问题与未验证范围

- 定向日期审查中，修正版仍有 3 次空测试调用，虽然已正确报告无覆盖；“不机械运行空测试”尚未稳定落实。
- 修正版文案审查共返回 6 条无关 Skill 关键词命中；一次验证建议涉及 fixture 中不存在的状态。没有执行整套状态验证，但建议范围仍可能偏宽。
- 日期类型支持义务在 fixture 中没有明确，两侧都出现过将额外类型差异分类为确定缺陷的观察；该材料不足以判断类型契约。
- 部分 CLI 复合命令只保留末尾输出。只有退出码足以证明前序成功的 `&&` 链才可结合源码核对；其他缺失证据保留为未验证。
- 此次测试显式指定本地入口，不证明 description 的自然触发准确率；没有真实 CodeGraph、浏览器视觉、其他 Harness 或复杂生产项目验收。
- 评测运行器已在当前 macOS 环境执行；Windows 适配未验证。当前用户级安装仍为 `1.4.0`，本次没有提交、推送、发布或重装。
