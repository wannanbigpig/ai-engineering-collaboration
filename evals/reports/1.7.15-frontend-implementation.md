# 1.7.15 前端 Skill 落地调整

## 目标与修改

针对用户反馈“只讲原则，落地效果差”，保持触发 description 不变，调整 `frontend-ui-ux` 的执行内容：

- 编码前落实页面骨架、实际颜色/字体/间距等视觉规格、交互及窄屏重排；新页面有与内容相关的视觉重点。
- 按选定规格完成可运行主路径，再补齐任务需要的状态；按钮、导航和提交连接真实契约。
- 打开实际页面并操作，按内容与操作阻塞、布局层级、视觉细节的顺序修正。
- 按需参考给出已有业务界面、新内容页的具体骨架、数值选择与渲染问题到代码修正的映射。

原有设计系统、局部修改、只读和仅方案边界保留。没有引入固定审美、组件库、外部服务或强制截图轮数。开源来源与许可见[研究说明](../../docs/frontend-skill-research.md)，star 不作为效果证据。

## 结构验证

`python3 -B scripts/validate_repository.py --tests` 实际执行通过：11 个 Skill 的 Agent Skills schema、版本与独立资源检查、差异检查，以及 253 项单元测试。测试中预期失败夹具会打印尾随空格或版本不一致的诊断，完整测试结果为 `OK`。

这些结果支持包结构与已测工具契约，不证明页面视觉或 Agent 行为已经改善。

## 真实任务方法

旧版使用本次前端修改前的完整工作区快照，包含此前尚未提交的 1.7.15 文档改动，不以旧提交替代它。候选冻结本次 Skill 内容。各自使用独立临时工作区、相同原始 TASK、相同本地预约 API，只安装对应版本的 `frontend-ui-ux` 并显式要求读取。

新任务为“巷口修车课”页面：三门真实输入课程，包含无场次、满员、联系信息校验、核对、首次合法请求 503、重试及真实回执。原始输入在运行前固定，评分预声明在另一个非祖先目录中，没有复制给模型。它是本次开发比较样本，不作为未经接触的统计保留集。

两次调用指定 `gpt-6.1-sol`、Codex CLI 0.164.0、900 秒上限、`--ignore-user-config`、`--ephemeral`、`workspace-write` 和 `approval never`。哈希、精确命令、调用前后环境观测、完整 trace、stderr 和失败均保存在本地 `.aitasks/evaluations/frontend-implementation-20261106/`。运行脚本为本次维护者使用的临时证据工具，不新增为 Skill 的日常执行依赖。

本比较只检验显式加载后的内容执行，不能证明自然触发。`--ignore-user-config` 和禁用外部 Skill 列表不意味着严格环境隔离，额外读取、配置漂移及接口失败须单独复核。主机浏览器的独立复查也不能冒充执行 Agent 自己完成了浏览器验证。

## 主机浏览器独立检查

使用主机 IAB，分别启动原 API 的全新进程，检查 1440×900 与 390×844 视口。主机没有向执行 Agent 传入观察结果，也没有修复模型生成的页面。保存了截图、DOM 和 HTTP 回执；最终核对测试文件与 Agent 产物的哈希一致，`server.py` 与原输入一致。

候选在首次主机检查后又修改了场次刷新状态及重复选择逻辑。该中间产物证据保留；随后另启动最终产物服务，重新检查空状态、字段错误、刷新保留输入、核对、首次失败、重试及桌面/手机成功路径，最终结论取该版本。

实际观察：

- 两版可查看三门课程，选择无场次课程时有恢复指引，已满场次不可选；空姓名/手机号有对应反馈并定位字段。
- 两人预约在确认前展示正确课程、时间、地点、单价 ¥129 与合计 ¥258。确认时控件禁用并有等待反馈；服务首次拒绝后保留信息，重试成功。
- 桌面及手机各完成一次两人预约，分别得到真实 `YC-0001`、`YC-0002`。独立 GET 核对课程、日期、联系人、单价、人数、金额和地点一致；余量由 4 减为 0，第三条回执不存在。
- 实际使用 Enter 执行选择、核对、确认与重试，Tab 可从姓名到手机号；观察到焦点位置和关键控件。没有据此声称完成全部键盘、读屏或无障碍验收。
- 两版手机布局未出现整页横向溢出，关键字段与动作可达。候选桌面把课程选择与预约表单并列，关系更直接；旧版采用分步填写，两种结构都能完成任务。

视觉仍有待改之处：两版窄屏标题均有不自然断行，候选还出现日期末字单独换行。该观察保留，不把“可以预约”升级为“视觉完美”。截图与主流程不能覆盖真实设备、读屏、打印结果、所有网络故障或并发情形。

本次观察到候选在显式加载后生成具体页面，其最终产物在上述主机检查中可操作；不能证明候选普遍优于旧版。真实渲染环节仍依赖执行环境，缺少它时也不能由更多原则或单元测试替代。
