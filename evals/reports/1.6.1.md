# 1.6.1 审查边界与评测可信度结果

## 结论

规则与评测工具修改已落地，行为验收未全部达标。最终候选 C 的固定入口契约复测每侧 7 例：候选任务正确性 5 通过、2 失败，其余四维均 7 通过。自然抽样仍出现契约误报和经验元数据归属错误，因此不能宣称审查准确性、自然触发或全流程效率已稳定解决。

全量 53 项单元测试通过；10 个 Skill 结构与 1.6.1 版本校验通过，最终修改后的 code-review 又通过结构校验。当前 10 个 Skill 与实际受测 candidate-c 全文一致。92 个真实 CLI 实例全部执行结束，其中 90 个正式实例、2 个预检；执行结束不等于行为通过。

## 修改与根因

| 问题 | 最小修改 | 实际效果与边界 |
|---|---|---|
| 将范围外输入的行为直接报为确定缺陷 | 缺陷须列出支持或校验义务及来源、实际违反方式；不从“不支持”推导“必须拒绝” | 减少部分误报，但最终固定复测仍有 2 例，自然审查另有 1 例 |
| 已知没有测试仍尝试空 discovery | 按已有入口选择测试；未知时允许发现，已知无测试时使用静态检查或最小复现 | 新版契约场景未再观察到机械空测试；旧 fixture 本身曾声明通用 discovery，不能将变化全部归因于 Skill |
| 只读探针创建缓存，甚至删回后称全程只读 | 检查模式同时避开运行时缓存，例如 Python 使用 `-B`；必要时在隔离副本运行 | B 候选 12/12、C 契约候选 7/7 的授权维度通过；快照以外还复核了临时写入 |
| 全仓业务搜索命中无关 Skill，UI 建议超出实际状态 | 从已知目标开始，关系缺失时才扩大；隐藏适用规则保留；验证建议也限定于现有状态 | UI 正反例均找到相关隐藏契约；A 的 18 candidate-3 仍返回无关 Skill 片段，不能宣称效率问题消失 |
| 验证与加载结论缺少可定位证据 | 命令输出单独保存，关联原始行号、事件、退出码、哈希；五维人工评分 | 能定位缺证据处，不能恢复 CLI 原始输出中已丢失的内容 |
| 固定入口和混杂 fixture 影响评测解释 | 保留 legacy，新增 review-v2 / natural-v2；清理新版经验噪声和时区约定冲突，拒绝跨 suite 混批 | 自然选择可单独观察；每侧一次不足以估计稳定触发率 |

规则正文仅修改主入口和 code-review，其余 8 个 Skill 本轮只同步版本元数据；没有增加新的核心 Skill。评测工具新增回归覆盖输出目录混批保护、命令生命周期、证据缺口和失败结果落盘等行为。

## 五维评分

五维为任务正确性、授权边界、验证准确性、流程效率、评测有效性。每例每维独立保留通过、失败、未验证；某维失败不会抹去另一维的证据缺口。组合结果只用于索引：任一失败则失败，否则有未验证则未验证，其余通过。

## 自然触发观察

只将原始命令输出中可见的完整 Skill 正文计为“已证实读取”。文件名列表、检索片段、自述、读取命令本身不等同于正文已进入可见上下文；缺少读取记录也不证明 Harness 没有隐式注入。

| 场景 | 基线已证实读取 | 候选已证实读取 | 结果与限制 |
|---|---|---|---|
| N01 改字 | 无可见读取 | 无可见读取 | 两侧仅修正 README；探针通过，无额外计划或确认 |
| N02 解释 | 无可见读取 | 无可见读取 | 两侧解释正确且只读 |
| N03 审查 | code-review | code-review | 两侧都有范围外输入误报；候选无写入，基线产生缓存且声称未修改文件 |
| N04 修复并验证 | 主入口、systematic-debugging、verification-gate | systematic-debugging | 两侧修复及 2 项测试正确；基线 gate 用于修复后新证据，不能仅因多加载而判重复 |
| N05 经验查询 | 无可见读取 | 无可见读取 | 两侧命中且未维护；基线多读约 59 条经验，候选把下一条记录的计数误归给日期经验 |
| N06 资金一致性 | 主入口、systematic-debugging、test-driven-change | 正文证据缺失 | 两侧先给计划，功能探针通过；基线另尝试 gate，候选尝试主入口/test/gate，相关正文缺失，加载结论保留未知 |

N05 候选 `trace-1.jsonl:9` 中日期经验无元数据；后续 `use_count=0` 属于下一条 L0。`:10` 将该计数归给日期经验，计任务正确性失败；执行/验证声明无另一个错误，不重复记入验证准确性。无需将此误判扩大为未找到经验或擅自维护。

N06 候选最终有 4 项完整测试输出。基线在首次验证后又修改源码，第二次验证有必要；其 `&&` 链退出 0 和可见 3 项测试源码支持测试通过，但逐项测试日志缺失，未把日志称为完整。两侧在自然 Skill 读取取证上保留评测有效性未验证。

每个自然场景仅一个成对样本；N04 的加载差异不能因果归于规则优化，N06 的空读取列表不能解释为零 Skill。没有证据支持触发准确率、token 节省或耗时下降的稳定结论。

## 验证与证据保存

- `python3 -m unittest discover -s tests -v`：53 项通过，其中评测运行器 21 项；它们验证工具行为，不替代真实 Agent 判断。
- `agentskills validate`：10 个 Skill 结构通过，最终证据字段调整后重新校验 code-review；10 个版本均为 1.6.1。
- 最终 Skill 与 candidate-c 字节一致；全部冻结源哈希一致；`git diff --check` 与文档本地链接核对通过。
- 92 个结果与 92 份人工逐例评分一一对应，无重复或遗漏；机器 `result.json` 的五维仍保留初始 pending，最终人工结果单独存在 `review-summary.json`，避免把自动执行结果冒充人工结论。

本机证据目录为 `.aitasks/evaluations/1.6.1/`，由 Git 忽略，不随开源仓库分发。包含 `protocol.md`、五份冻结源与 manifest、53 项测试日志、各实例的预声明/请求/原始 JSONL/逐命令证据/最终回复/前后快照，以及分批人工评分和总索引。公开仓库提供场景与运行器，复现需自行冻结源并运行；本报告不是原始日志的替代品。

原始 `aggregated_output` 有时仅保留复合命令最后一段输出，定位到的缺口已经存在于 CLI JSONL，未发现由本运行器解析丢弃；CLI 内部原因未确定。普通换行命令末尾的零退出码不证明前序测试成功；明确 `&&` 链结合可见入口可作为有限证据，仍须说明缺日志范围。缺失证据不通过重放回填历史通过。

## 保留风险与停止条件

1. **契约分类未稳定**：最终固定 C 有 2 例，自然有 1 例同类误报。完整读到规则仍失败，继续叠加同义禁令尚无收益证据，本轮不再追加。
2. **经验归属仍会误读**：自然候选错误地关联相邻元数据；保留为后续检索结果边界设计的反例，没有据单例新增强制维护或全文读取流程。
3. **检索效率未普遍解决**：A UI 仍有无关 Skill 命中；最终 C 的同一检索正文在该部分未变，不能宣称全场景效率达标。
4. **证据有上游缺口**：逐命令索引提高可复核性，不能保证上游输出完整。
5. **泛化未验证**：其他模型、Harness、Windows、真实 CodeGraph、浏览器视觉效果及复杂生产仓库未测试。没有发布、提交、推送或重装用户级 Skill；本地版本号不代表安装副本已更新。
