# 变更影响分析

修改前追踪受影响路径、数据流和风险，先分析后实施。

## 追踪清单

只检查与当前变化相关且尚未明确的路径；复用已有调用链与风格基线，不重复调查已核实部分。按变更类型选择：

- **入口与调用链**：页面/CLI/交互入口、API/命令/事件、Controller/Service/Model 定义及调用方。
- **复用检查**：新增函数、模块、接口或兼容分支前，在受影响范围内检索已有实现、扩展点和项目惯例；说明选择复用、扩展或有意保持重复的理由，不因名称不同就断定行为不同，也不强制跨业务边界抽象。
- **风格与界面基线**：按受影响部分核对同类实现和共享设施，复用已有基线。后端关注相关分层、校验、错误或事务约定；前端关注相关组件、状态、API 或样式约定。没有明确 UI 设计时，以目标模块的同类页面、共享布局、组件和设计令牌为参照；只在布局、交互或状态行为受影响时检查对应响应式及加载/空/错误状态，文案修改核对目标文本和溢出等直接影响即可。找不到可靠参照或现有模式冲突时说明依据，不以个人偏好补造规范。
- **数据与异步**：读写、校验、转换、Job/事件/队列/定时任务、重试和幂等。
- **边界与契约**：权限、数据范围、租户隔离、输入输出、序列化、错误码、缓存一致性。
- **基础设施与协作**：迁移、索引、跨仓库 reader/writer、测试、部署和回滚。

## 方法与输出

- 从入口沿受影响路径追踪定义、调用方和数据流；已知目标和局部关系直接检索、读取，尚未明确的结构或跨模块关系在已接入 CodeGraph 时优先用图谱定位。不可用或结果不足时用自身可用的检索工具补足。
- 打开并核对实际实现，不根据符号名或单一调用点猜测。
- 输出受影响文件/模块、风险等级、证据和需要额外验证的路径。

## 边界

本阶段只分析、不修改文件，无法确认的路径标记未验证。输出结论和剩余缺口后返回调用方；已有实施授权的任务可继续实施，不因完成分析重复询问。独立的只读分析在交付结论后停止，无需为标记未验证加载其他 Skill。
