# 验证关卡

核对证据是否足以支撑当前声明，只补缺口。每项结论需要当前、可复核的证据；进入本 Skill 不使已有有效证据过期。只读审查完成与功能修复完成是不同声明，验证范围随声明确定。

## 流程

1. **定义证据**：列出直接证明结论的测试、Lint、类型检查、构建或业务路径命令，并说明各自证明什么。
2. **复用或补跑**：已有结果包含命令、范围、输出和退出码，且工作区相关内容、依赖、配置和环境未变时直接复用，包括可核对的独立验证产出；仅输入变化、证据缺失或过期时重跑相关命令。
3. **检查结果**：核对足以支撑结论的输出、关键断言和退出码；仅缺少会影响判断的内容时补取，优先读取保留日志，不因无关日志截断重跑。
4. **区分类型**：测试、Lint、类型、构建和业务路径分别判断，不能用一种通过替代另一种。
5. **验证项目一致性**：复用风格基线及已完成的相关检查；根据项目明确要求和变更风险选择 formatter、Lint、类型检查或测试，不默认全套执行。formatter 默认使用检查模式，自动修复只限获准修改的文件，不能格式化无关内容。UI 发生变化时，只验证实际受影响的布局、交互与状态；可用环境中打开页面进行视觉核对，编译或构建不能替代视觉证据，无法运行时标记 UI 未验证。
6. **检查结构质量**：已有实施阶段的结构复核且 diff 未变时复用；否则仅在本次 diff 和受影响范围内检查新增的等价逻辑、无依据的文件/函数/分支、平行实现、死代码、临时兼容层、错误掩盖和过度拆分；评估调用层级、跨文件跳转、参数传递与上下文恢复成本。函数长度只作为调查信号；单次使用且只转发参数或改名的小函数，如果没有独立业务语义、真实复用、清晰的测试/副作用边界或实质复杂度收益，应就近保留或内联。优先使用项目已有工具，本阶段默认只检查和报告；必要修复应回到已授权的实施范围，变更后只重跑受影响验证。不要默认扫描全仓、强制抽象合理重复，或为美观扩大任务范围。
7. **核对量化结论**：重复率、圈复杂度、覆盖率、漏洞数等数字必须附实际执行的工具、版本、范围和输出；未运行对应工具时只能给出定性观察并标记“未验证”，不得把模型估计写成测量结果。
8. **决定声明**：功能证据、项目一致性与适用的结构证据覆盖关键点且通过才宣称完成；部分通过要说明范围。

## 未验证

因环境、依赖、权限或外部系统无法验证时，明确写“未验证”，说明原因并给出可执行的后续方式。关键验收未验证时不得宣称功能已完成；只读审查可以完成，并明确哪些运行行为尚未验证，不将不适用或未要求的检查当作阻塞项。禁止以删除或弱化测试、跳过校验、吞异常或硬编码通过测试的方式制造“通过”证据。
