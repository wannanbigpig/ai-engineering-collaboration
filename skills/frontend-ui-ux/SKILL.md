# 前端界面设计与体验

围绕真实用户要完成的任务设计清晰、有整体感的界面，兼顾可用性、视觉质量与实现维护成本。页面的用途和用户决定设计方向，不把同一套视觉风格套到所有产品。

## 使用边界

- 新建用户可见的页面或组件，或需要评估、改善已有界面的视觉、布局、信息组织和交互时使用；没有视觉或交互目标的纯逻辑、普通文案和后端修改直接处理。
- 用户只要求评估时保持只读；已要求设计或实施时在授权范围内继续，不因加载本 Skill 再次询问。不自动发布或仅因进入本 Skill 加载其他专项；仍遵守用户和项目要求的任务维护与验证，新增外部依赖须有任务依据。
- 从需求、已有实现和项目规则推导用户、任务与约束；只有无法从证据确定且会改变交付的关键选择才询问。小范围修改只做与该处有关的设计判断。

## 设计与实现

1. **理解场景**：先识别主要用户、最重要的任务、需要呈现的真实内容和操作；检查相关页面、组件、样式、设计令牌及受影响行为。有明确设计稿或项目规范时遵循它们，没有时结合产品用途形成简短的布局与视觉方向。
2. **选择合适的表达**：管理与数据界面优先让信息易查找、比较和操作，保持适当密度；展示与营销页面围绕内容组织视觉重点；儿童界面根据实际年龄与能力控制信息量、文字和交互难度。其他产品按其使用场景判断，不把装饰、特效或固定模板当作质量目标。
3. **建立视觉层级**：明确主要内容与动作，通过布局、对齐、留白、字号、字重和色彩形成一致且可读的层次；相同功能保持可辨认的样式。卡片、分隔、图标和动效应有明确作用，避免堆叠相同卡片、无意义标语和次要标签。若说明文字承担了本应由布局或命名表达的关系，调整相关结构；保留必要标签、状态、错误解释与操作指引，不虚构数据或用户内容。
4. **兼顾实现与使用**：优先复用现有组件、设计令牌和技术栈，让样式与状态易于开发者和 Agent 定位、理解及验证。用户明确要求改善外观时，可在授权范围内调整不合理的视觉层级和局部样式，不机械复制已有问题；跨页面的系统性改造按实际任务范围处理。不为某个模型偏好引入第二套视觉体系、组件库或外部服务，也不把设计过程写进面向用户的界面。
5. **保护交互与契约**：保留既有数据、操作、导航、权限及错误语义，除非用户明确要求改变。对受影响的控件检查可理解的名称、键盘与焦点、状态反馈、文本可读性和适用的触屏与响应式行为；加载、空和错误等状态按实际存在且受影响的范围检查。动效应服务操作，并尊重减少动态效果的设置。

## 验证与交付

- 根据变化运行最相关的功能检查；涉及视觉或交互时，在环境允许的情况下通过浏览器打开实际页面，原生应用使用适当的模拟器或设备，核对受影响内容、操作及代表性的视口和状态。必要时比较修改前后，关注溢出、遮挡、长文本和主次关系；不固定要求所有视口和状态。
- 构建、静态检查或测试通过不能代替视觉核对。不能打开页面或无法执行相关操作时，说明未验证的部分与原因；不把样式存在或截图生成当作真实用户体验已验证。
- 交付说明关键设计取舍、实际验证结果和剩余限制。保持用户、开发者及 Agent 体验中受本次任务影响的方面得到改善，其他方面不退化；不为凑齐改善而扩大为无关重构。

设计取舍不清楚时按需参考[后台、内容页与只读边界示例](references/examples.md)，不要求每次加载或套用示例布局。
