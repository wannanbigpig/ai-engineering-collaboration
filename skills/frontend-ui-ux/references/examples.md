# 按任务选择设计与验证

仅在当前设计取舍不清楚时查对应例子。这些是决策示例，不是固定视觉模板，也不是已通过的用户研究结论。

## 已有后台：筛选与提交混淆

用户要求改善退款列表的视觉和操作布局，保留接口与已有功能。

- 先核对筛选字段、退款表单、按钮的真实归属与提交目标，以及现有组件和令牌。
- 如果筛选与退款挤在同一视觉组，按任务分区，给退款保留清楚的主要动作和金额单位；不要靠新增大段操作说明替代布局判断。
- 必要的状态、错误原因、字段标签、键盘焦点和权限反馈必须保留。界面精简不改变 HTTP 方法、字段名或重复提交语义。
- 验证实际筛选与退款操作，在受影响视口检查长标签、溢出和焦点顺序；对比截图只说明视觉变化，不替代提交验证。

交付可以说明：“把筛选和退款分为两个操作区，保留金额标签与错误反馈；已验证筛选和退款提交；未执行的状态单列。”不能只以构建成功声明体验改善。

## 新内容页：亲子活动信息

用户提供图书馆活动名称、时间、地点，要求做一个易读页面。

- 以活动信息和读者浏览顺序决定层级：活动名称、时间地点、必要说明；没有报名入口的需求和数据时不虚构报名、余票、用户评价。
- 根据内容选择排版、色彩和适当插图，不复制后台表格，也不因“亲子”就假设操作用户是幼儿。
- 在实际页面检查活动信息可见且正确，窄屏不截断时间地点，颜色和文字可辨认；有链接或控件才验证对应交互。
- 项目已有字体、组件和资源时优先复用；新增外部字体或服务须有任务依据，不能为了示例强加依赖。

## 只读评估与明确文案修改

| 请求 | 当前动作 | 完成边界 |
|---|---|---|
| 只读评估布局与操作 | 查看实际页面和受影响流程，区分已观察问题与待验证建议 | 不写源码、截图到项目目录、记录或计数；如需截图证据使用任务允许的外部临时位置 |
| 仅将“提交”改成“保存” | 核对词义、既有状态文本及直接溢出风险 | 不增加设计阶段或全站改版；若语义存在真实冲突，先说明证据 |
| 只读审查表单代码 | 使用已有审查能力核对归属、标签和行为契约 | 不因文件是前端代码自动转为视觉重设计 |

## 记录可复核证据

对确实需要视觉验证的任务，记录页面/路由、视口、操作、观察结果及截图位置即可。状态和视口按实际影响选择；无法打开页面时说明原因，不补造截图或把示例效果当作本次结果。
