# `.aitasks` 维护

代码编辑任务自动维护一条 todo；用户明确要求或同一问题第二次实质出现时维护经验。只读任务不写记录。

## 触发与边界

- 编辑项目代码前创建或复用本任务的一条 todo；后续修改仍更新这一条，完成时写入实际结果并标记 `completed`，未完成保持 `active`，取消标记 `cancelled`。仅维护 `.aitasks` 不递归创建 todo。
- 用户明确要求记录经验时立即记录，不受次数限制。否则同一问题在当前或可检索的既往对话中第二次实质出现时自动沉淀；同一轮复述、重复命令输出、预期失败测试不算再次出现。先检索并更新已有同类经验，记录可证实的现象与做法；原因未证实时标注“未确认”，不写成根因。
- 用户要求只读或不修改文件时，不写 todo、经验、计数、忽略规则或归档。普通经验查询直接检索命中记录，不加载维护流程，也不更新计数。

## 写入规则

- `.aitasks/` 不存在时按需创建；首次创建前按 [维护参考](references/maintenance.md#首次创建与忽略规则) 核对 `.gitignore`，尊重用户已有跟踪选择。
- 新记录读取对应单条模板：[todo](assets/todo.md) 或 [经验](assets/lessons.md)。填入唯一 UUID4 十六进制 `id`，追加到活动文件尾部，不覆盖旧内容；复用保留原 `id`，旧记录不批量回填。todo 新建用 `status=active`、`completed_at=-`，经验新建用 `use_count=0`；核心经验可 `pinned=true`。
- 简单 todo 按模板只记录目标与范围、必要验证和实际结果；多步骤或高风险任务按需补步骤、依赖与风险，不强制空栏目，也不改写旧记录的结构。
- 经验确实用于解决问题且允许写入时才递增 `use_count`、更新 `last_used_at`；普通查询不计数。无有效元数据的旧记录不自动清理。

## 自动清理与工具

- 每次允许写入 todo 或经验后运行 `scripts/maintain_aitasks.py status`；达到阈值即执行 `cleanup --apply`。只把到期或超额的非固定记录先归档再移出活动文件，保留其他记录顺序，不自动删除旧归档。
- 元数据更新与批量查询优先用脚本；只更新状态或计数时不读模板。普通只读经验查询只取命中记录，勿运行 `status` 或 `cleanup`。
- 归档、失败恢复、命令参数和阈值按需读取 [维护参考](references/maintenance.md)。脚本需 Python 3.10+；不可用时按模板与参考的相同边界手动处理。

无归档授权时只预览，不删除或压缩旧归档。
