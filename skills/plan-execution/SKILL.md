# 方案实施

将用户已要求实施的现有方案、Spec、任务清单或明确步骤转为可验证的改动。计划是当前判断的依据，不是忽略代码变化或用户边界的授权。

## 触发与边界

当用户要求按已有方案实施，且计划已说明目标、范围和基本验收方式时使用。

- 缺少实施步骤但目标明确时，自行形成最小步骤；只有关键需求无法从证据推导时才需要 `requirements-framing`。
- 共享行为、跨模块数据流或契约影响尚未明确时，先补充必要影响分析；可用的 `change-impact-analysis` 由调用方按缺口选择。
- 只需要评审、调研或撰写方案时，不使用本 Skill。

用户明确要求实施即为当前范围的实施授权，阶段切换不重复确认；不自动创建提交、推送或拉取请求。只有当前会话或上层规则允许委派、任务独立且所有权明确时并行，否则串行实施，无需为此加载入口。

## 实现约束

- **防御有依据**：新增校验、兜底、重试或兼容分支须对应明确契约、可达失败路径或具体风险；仅凭“可能发生”不增加复杂度。有实质取舍时说明触发条件、依据和复杂度成本，不编造发生概率；额外加固不夹带实施，范围内必要修复沿用已有授权。
- **校验有边界**：在外部输入进入的信任边界校验或规范化；同一边界内、同一份已验证且约束未变的数据不逐层重复检查。外部服务、持久化读取或异步消息若带来新的不可信数据，按契约处理；类型正确不代表权限或业务状态有效，保留必要的权限、事务、并发与幂等保障。
- **抽象有收益**：优先就近表达连续流程；真实复用、可清晰命名的独立概念或实质复杂度下降才提取函数。单次使用不禁止提取，但不为“主函数只留正常流程”把每个校验与步骤机械拆开；短 guard clause 可留在原处。
- **维护有源头**：注释解释不明显的约束、原因或反直觉行为，避免复述代码；生成文件修改源定义并用仓库现有流程重新生成。缺少生成条件时说明缺口，不用手改产物替代；沿用现有工具，不为本次实现另建流程。

## 实施过程

1. **复核可执行性**：复用方案、相关规则和验收条件；核对工作区状态，仅重读有变化、上下文缺失或存在并发修改迹象的目标文件和依赖，沿用已确认的局部风格基线。方案与当前代码冲突时，不按旧假设直接实施。
2. **确定下一切片**：选择最小且可独立验证的改动，说明本片的验收方式和真实前置依赖；没有依赖不另建依赖表。显式要求高于仓库默认，未规定的代码结构与 UI 沿用风格基线，优先复用现有基础设施、组件和设计令牌，不凭模型偏好建立第二套分层、组件或视觉体系。将配置、测试和文档工作纳入其所属交付，而不是拆成无验证价值的步骤。

   同时评估用户完成任务、开发者理解维护与排查、AI Agent 定位实现、理解契约和验证修改的成本；在本次范围内改善相关方面，其余不退化，不为凑齐三项改善扩大范围。除明确要求改变的行为外，保持现有功能和契约兼容。

   涉及 UI 时，精简无助于理解、判断或操作的标语、重复说明和装饰性标签，保留必要名称、业务解释、状态、操作指引与无障碍信息。若仍需大量说明，先检查信息层级、分组、命名和操作路径；确认布局问题后调整受影响区域，不直接扩大为整页改版。CLI、帮助和面向用户的错误提示按同一信息价值原则处理；纯后端内部实现不套用界面删减标准，不能据此删减契约字段或诊断所需的信息。

3. **实施并按需验证**：需要回归保护时复用已有失败测试或新增行为测试，可参考已可用的 `test-driven-change`；当切片达到可交付边界，或验证结果会决定下一步时运行最相关的检查，相邻低风险改动可合并验证。预期失败测试不触发重规划，代码和运行条件未变的通过结果供交付复用。
4. **处理偏差**：非预期失败才补充根因调查；未知共享行为或契约影响才补充影响分析；不能从事实推导的关键业务决策才询问。由入口调用时返回缺口，不自行递归加载专项；独立使用时自行完成能力范围内的最小调查，只暂停受影响部分。
5. **结构复核**：行为验证通过后对本次 diff 与受影响实现做一次检查，确认没有新增等价逻辑、无依据的平行路径、错误掩盖或临时代码；同时权衡内聚性与调用跳转成本，函数长度只作为调查信号，不按行数机械拆分连续流程。核对受影响操作、维护排查、Agent 定位与验证路径是否出现退化，以及必要信息、既有功能和契约是否保留；不能仅凭代码或文案变短判断体验改善。需要整理时只做能独立验证且属于目标范围的调整，不扩大为无关重构。
6. **完成交付**：汇总切片验证与结构复核证据，检查是否覆盖交付；仅有额外证据缺口时需要 `verification-gate`，明确需要独立审查时才追加 `code-review`。不因进入收尾重复运行已通过且输入未变的检查。

## 完成标准

已确认每个方案交付都有相应实现和验证证据；未实施项、偏差、假设和未验证内容均已明确。不得仅因计划中的步骤已勾选就宣称完成。
