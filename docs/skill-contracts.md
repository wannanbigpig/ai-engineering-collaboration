# Skill 职责、依赖与验证

本文件供维护者检查规则是否漂移，不是 Agent 每次执行任务必须加载的公共流程。

## 规则所有者

| 规则 | 权威位置 | 其他位置保留什么 | 验证方式 |
| --- | --- | --- | --- |
| 用户授权与只读边界 | 用户/项目规则；入口负责跨阶段传递 | 独立专项保留最小边界，不能依赖入口先加载 | 只读文件快照与轨迹、已授权实施负例 |
| 专项选择 | 各 Skill 的 description 与使用边界；入口负责组合优先级 | 不复制全套路由到每个专项 | 自然请求、近似负例与显式入口分别评测 |
| todo、观察、经验、归档 | `aitasks-maintenance` 的正文、模板及脚本；只读解析统一由 `query_aitasks.py` 实现 | 四个消费者包含受校验的只读生成副本，不复制维护写入能力 | 幂等、失效、归档、独立查询及跨会话回归 |
| 缺陷与建议分类 | `code-review` | 其他专项返回证据和缺口，不另造缺陷门槛 | 当前契约的支持/拒绝/未定义正反对照 |
| 验证与证据复用 | 所属专项执行必要验证；`verification-gate` 补真实缺口 | 入口汇总已有证据，不要求重新运行 | 输入不变复用、输入改变复验、错误声明反例 |
| 视觉设计 | `frontend-ui-ux` | 实施与审查只核对实际受影响范围 | 实际页面、交互、视口及独立复核 |
| 安装与发布内容 | `bootstrap_project.py` 的分发清单与版本；打包器复用 | 文档引用同一命令，不复制多份安装逻辑 | 缓存过滤、真实定制保护、确定性打包 |

少量重复的授权和只读边界用于保障独立安装。只有重复造成漂移或实际加载成本时才抽取，不能要求所有任务先加载公共大文件。

## 独立安装和可选能力

1. 每个 Skill 的 Markdown 本地资源链接都留在自身目录内；`validate_repository.py` 递归核对这些资源，单装不依赖兄弟目录。
2. 使用另一 Skill 的能力时，先按名称在当前可发现目录中定位它，存在才读取该目录中的资源。安装范围可能不同，不能拼接固定 `../` 或用户主目录。
3. 只读经验查询不依赖维护 Skill 同装：工程入口、审查、调试和影响分析包均包含同源 `scripts/query_aitasks.py`，Python 3.10+ 可直接运行。维护工具缺失或旧版不支持时使用本包脚本；无 Python 时仅取少量标题及元数据线索，正文与适用性未核实时保持未验证，不现场再造解析器。
4. 本仓库工程入口用于代码编辑，或项目启用自动 todo 规则时，需要可用的 `aitasks-maintenance`；这项依赖来自工作流约定，和只读查询的可选依赖分开说明。
5. 其他专项未安装时，在已有授权内采用等价最小能力，说明限制；不要递归加载入口或重复索要已给出的授权。

资源检查只证明包内容自足。可选发现及回退是否真的发生，仍须在目标 Harness 中执行对应场景，不能由链接校验推断。

`scripts/sync_query_tools.py --write` 从维护 Skill 的权威脚本和别名资产生成四包副本；`validate_repository.py` 与打包预检会拒绝副本漂移。维护 CLI 和独立包执行同一个只读实现，解析规则不因安装范围分叉。

## 容易混淆的选择

| 当前证据/请求 | 合理选择 | 不应因而扩展 |
| --- | --- | --- |
| 已有方案，用户明确要求实施 | `plan-execution`，先对照当前实现 | 再次要求批准原方案 |
| 测试已定位根因，修复范围清晰 | 直接最小修复及必要回归 | 重启整套根因调查 |
| 只读审查表单代码 | `code-review` 或等价审查 | 自动进行 UI 重设计 |
| 改善筛选与提交的视觉关系 | `frontend-ui-ux` 或等价设计 | 更换组件库、重构无关页面 |
| 只解释函数或改明确文案 | 直接处理通常足够 | 强制入口、影响分析或设计阶段 |
| 失败原因或接口事实可从仓库查出 | 先检查当前证据 | 让用户回答可检索事实 |

这些是维护者设计评测的例子，不是唯一合法 Skill 序列。评分看任务正确性、实际缺口、授权与成本，不因模型选择等价能力就机械判失败。

## 开源参考与采用范围

2026-11-06 核对以下原始资料；采用机制与独立实现，不复制第三方 Skill 正文。

- [Anthropic skill-creator](https://github.com/anthropics/skills/blob/ca45fc496a3436251f191354091d557da31c15b5/skills/skill-creator/SKILL.md)：借鉴触发正反例、版本/无技能对照和重复观察。最终保留集不参与描述调优，不把优化集的最好结果作为泛化证明。
- [Superpowers writing-skills](https://github.com/obra/superpowers/blob/22f0b463e7a5e579904dd6211a520321035526f7/skills/writing-skills/SKILL.md)：根据失败类型选择表达形式；不引入所有任务强制技能、强制审批或统一全流程。
- [Vercel agent-skills](https://github.com/vercel-labs/agent-skills/blob/1a2c79d4e6c4a2283dc2c614b6538cbe1ed5ca62/scripts/build-discovery-index.mjs)：借鉴独立资源、可复核摘要及分发产物；本仓库不因短 Skill 的行数而机械拆分规则文件。
- [Agent Skills 规范](https://agentskills.io/specification)：元数据发现、正文激活和资源按需读取分层；格式兼容不等于 Harness 已验证。

## 变更验收

规则调整先说明具体失败或待验证假设。工具变更用真实输入输出和副作用回归；规则变更用受影响行为场景。只保留有收益或修复明确契约缺陷的变化，允许撤回没有证据的措辞实验。原始失败、环境缺口和历史结果不覆盖。
